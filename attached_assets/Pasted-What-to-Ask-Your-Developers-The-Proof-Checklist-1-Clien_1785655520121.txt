What to Ask Your Developers (The Proof Checklist)
1. Client-Side Request Queueing (Tier 1)
What to Ask: "Can you show me a video recording or live demo of the app handling a backend restart mid-conversation?"

The Proof Required:

Have them send a message in the web/mobile app.

While the message is pending, stop sirius-api on the server for 20 seconds.

Expected Proof: The UI should display a subtle "Reconnecting..." status (not a crash or error toast), queue the message locally in IndexedDB/AsyncStorage, and automatically deliver it the moment the API comes back online.

2. Automated Nightly Chaos Audits (Tier 2)
What to Ask: "Can you share the latest audit log output or report generated by the 3 AM chaos script?"

The Proof Required:

A copy of the audit log file (e.g., /var/log/sirius/chaos_audit.log or similar).

Expected Proof: The log should show:

Timestamp of the fault injection (e.g., stopping sirius-api or filling /tmp).

Timestamp of detection by the watchdog.

Total recovery time measured in seconds (confirming it is under your 30-second target threshold).

3. Semantic Log Analysis (Tier 3)
What to Ask: "Can you show me how Sirius or the watchdog surfaces error trends from PM2 logs?"

The Proof Required:

A sample output of the log analysis tool or incident report.

Expected Proof: A summarized breakdown showing log warning counts, latency spikes, or error frequency trends over the last 24 hours parsed directly from PM2 log files.

4. Zero-Downtime Nginx Port Swap (Tier 4)
What to Ask: "Can you run a deployment test while executing a continuous ping/curl loop against the API?"

The Proof Required:

Terminal output showing a script hitting /health every 500ms while a new code bundle is deployed to the secondary port (e.g., 4001) and Nginx is reloaded.

Expected Proof: Zero 502 Bad Gateway or dropped HTTP requests during the entire deployment window (200 OK across all requests).
