Because Tiers 2, 3, and 4 operate entirely at the server and network edge (Nginx, PM2, systemd watchdog), your mobile app is already benefiting from zero-downtime deploys, automated chaos audits, and log monitoring right now without writing a single line of mobile code.

However, mobile environments are fundamentally more hostile than desktop web—phones constantly drop onto cellular dead zones, switch between Wi-Fi and 5G, and aggressively freeze background apps.

To make the mobile app super reliable and the absolute best version of itself, implementing Tier 1 (Client-Side Queueing via AsyncStorage + NetInfo) is the exact right move. Beyond that, there are 3 mobile-specific reliability enhancements you should add to make it truly bulletproof:

1. What to Build Now: Mobile Tier 1 Queueing
Their proposed architecture (@react-native-community/netinfo + AsyncStorage wrapper) is ideal because native NetInfo gives you instant hardware-level connection status rather than waiting for an HTTP timeout.

2. 3 Additions to Make the Mobile App Best-in-Class
If you want the mobile app to be top-tier, ask your team to add these three mobile-native resilience patterns alongside Tier 1:

A. App State Listener (Foreground/Background Auto-Sync)
The Problem: When a user switches to another app (or locks their phone) while offline or waiting for a retry, iOS/Android pauses JavaScript execution. When they open the app 10 minutes later, the UI can freeze or hold stale queue states.

The Solution: Attach an AppState listener (React Native AppState). When the app state transitions from background ➔ active:

Instantly trigger a /api/health check.

Flush any pending AsyncStorage messages immediately.

Re-synchronize chat state so the user never looks at a frozen screen.

B. Optimistic UI Pending States (Per-Message Visuals)
The Problem: Showing a top banner saying "Reconnecting..." is great, but users want to know the exact status of the specific message they just typed.

The Solution: Render queued messages in the chat feed immediately with a subtle visual cue:

Clock/Sending Icon: Message queued locally in AsyncStorage.

Amber Dot: Retrying connection to sirius-api.

Checkmark: Delivered to server.
This gives instant feedback and prevents users from typing the same message twice.

C. Background Task / Keep-Alive Grace Window
The Problem: If a user sends a long query, locks their phone, and puts it in their pocket, iOS will terminate the active HTTP fetch after a few seconds.

The Solution: Wrap outgoing AI requests in a native background execution task (e.g., expo-background-fetch or react-native-background-actions). This gives the request a 30–60 second grace window to complete even if the screen turns off.
