## Rule

`SendOpenaiMessageBody` in `lib/api-zod/src/generated/api.ts` must include ALL fields the backend reads from `body.data`. Zod strips unknown keys by default. If a field is missing from the schema, it is silently `undefined` at runtime — the handler won't error, it just won't activate that feature.

**Required fields (as of June 2025):**
```ts
zod.object({
  content: zod.string(),
  userId: zod.string().optional(),
  mode: zod.string().optional(),          // "think" | "research" | undefined
  imageBase64: zod.string().optional(),   // uploaded image
  documentBase64: zod.string().optional(), // uploaded file
  documentName: zod.string().optional(),  // original filename
}).passthrough()
```

**Why:** The schema is generated by orval from an OpenAPI spec that only had `content` + `userId`. When new features were added to the handler (Think mode, Research mode, image upload, document upload), the schema was never updated. This caused mode-based features to silently fall through to Perplexity.

**How to apply:** After adding any new field to the `POST /api/openai/conversations/:id/messages` handler that reads from `body.data`, add it to this schema file. Also update `lib/api-zod/src/generated/types/sendOpenaiMessageBody.ts`.
